# PICK
<!-- impeccable:product-schema 1 -->

## Platform
adaptive

## Stack
Explicit user instruction: Expo Router for iOS, Android and web; local Node/TypeScript API with SQLite. No GitHub, cloud database, production data or public deployment. This POC defers the separate Next.js and PostgreSQL/Supabase architecture.

## Users
Parents, assigned drivers, teachers, gate staff and named home recipients reviewing shared synthetic school-to-home journeys across independent devices. Five Cedar Grove vehicles serve Maple and Oak classrooms; a separate Harbor School assignment exercises isolation.

## Product Purpose
Coordinate readiness, a vehicle visit and verified custody transfers. Make the current holder, uncertainty and next authorized action understandable. Traffic reduction remains a hypothesis to measure in a later pilot.

## Operating Context
School gates and mobile review on iPhone/Android; desktop supports side-by-side reviewers. All identities and eligibility facts are synthetic fixtures. Current task is a local proof of concept; the planning package remains the future pilot contract.

## Capabilities and Constraints
Approval, driver acceptance, explicit foreground arrival check-in, physical gate verification, shared vehicle order, classroom preparation priority, readiness, paired school observations, transport, paired recipient handoff, backup recovery, receipt resolution, reconnect and deliberate reset. Gate-only manual arrival and observed exception moves require reasons. Held vehicles stay in the physical lane until an explicit move is recorded. Ordering never authorizes overtaking or release. No background tracking, payments, enrollment, public signup or actual emergency service.

Actual foreground device measurements and explicitly labeled simulated samples are separate review paths. The server owns the configurable demo waiting zone and validates sample age, accuracy, coordinates and distance. Parent-trip, driver-assignment, teacher-classroom and recipient-handoff relationships constrain server access. iOS uses system native tabs; web and Android retain the shared JavaScript tab fallback.

## Brand Commitments
User requested restrained, readable, native-feeling task flows with accessible contrast, scalable text, safe areas and large touch targets. English initially, copy organized for later Spanish. Technical controls belong in Demo tools.

## Evidence on Hand
README and docs/01–06 define requirements and proposed architecture. No customer data, safety results, photos, ratings or traffic outcomes. Product truth recorded directly from the explicit implementation brief; no additional interview or standing visual preference inferred.

## Product Principles
Server-confirmed custody; explicit uncertainty; least-privilege views; no silent substitutions; no automatic replay of custody actions.

## Accessibility & Inclusion
Minimum 48-point targets, scalable text, descriptive controls, readable contrast, no color-only state and no required motion. Physical-device verification remains a separate reported check.
